## Scope decisions

- The portable-appliance product direction is implemented by plan 012 rather
  than duplicated as a second plan.
- The live-activity direction is plan 016. It is deliberately a design and
  measurement spike; shipping an alternate state model is outside its scope.
- Direct tracker/provider acquisition integrations are not planned. They would
  expand credential handling, protocol maintenance, abuse controls, and legal
  exposure before the existing Torznab/Newznab and external-client contracts are
  fully hardened.

## Findings considered and rejected

- Archive extraction traversal: existing confinement checks guard the inspected
  paths; no fix plan is justified.
- DLNA filesystem path traversal: `os.Root` confines media opens to the storage
  root; plan 001 addresses visibility policy, not path confinement.
- Cross-user request access: inspected request handlers enforce ownership; no
  authorization repair is currently evidenced.
- Embedded-engine shutdown leaks: shutdown waits for watcher termination; no
  lifecycle fix is needed outside the later composition-root maintainability
  plan.
- Discover fan-out: the behavior is intentional and cached; replacing it would
  add complexity without a demonstrated bottleneck.
- Dependency drift or a high-severity npm vulnerability: the audit found no
  actionable manifest drift and `npm audit --audit-level=high` passed. Plan 011
  adds the missing Go vulnerability gate instead of proposing speculative
  dependency churn.
