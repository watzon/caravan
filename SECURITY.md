# Security policy

## Supported versions

Until Caravan publishes its first stable release, security fixes are made on
the latest release line only.

## Reporting a vulnerability

Please do not open a public issue for a suspected vulnerability. Use GitHub's
private vulnerability reporting flow from the repository's **Security** tab.
Include the affected version or commit, deployment mode, reproduction steps,
impact, and any suggested mitigation.

Do not include live credentials, indexer URLs, API keys, library contents, or
personal data. Replace them with minimal synthetic values.

Private vulnerability reporting must be enabled before the public launch so
this policy always points to a working private contact path.

## Security-sensitive areas

Reports involving authentication or authorization, restricted-library
visibility, path confinement, archive extraction, credential storage or
redaction, remote download clients, and prepared portable drives are especially
valuable.
